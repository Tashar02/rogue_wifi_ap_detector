\begin{abstract}
Wireless network security in resource-constrained IoT environments requires proactive intrusion detection and resilient access extension. This paper presents a hardware-integrated Rogue Wi-Fi Access Point Detector and network extender built upon the modern RISC-V ESP32-C6 platform (broadcasting under the device SoftAP SSID \texttt{Scarlet ESP32-C6}). The system combines multi-functional operational modes including promiscuous frame interception, targeted ping monitoring, real-time AP traffic analysis, client station MAC logging, Denial-of-Service (DoS) traffic flood detection, multi-port honeypot deception (FTP, SSH, HTTP, HTTPS), and an automated Layer-3 Network Address and Port Translation (NAPT) Wi-Fi repeater. Featuring a state-driven single-button control mechanism, non-blocking asynchronous timing architectures, active acoustic feedback, and dual OLED/addressable RGB visual telemetry, the prototype delivers effective local threat detection and network bridging. Empirical evaluation demonstrates low-latency packet inspection, rapid honeypot connection termination, dynamic RSSI-based open network selection, and reliable packet routing under active flood alerts.
\end{abstract}

\section{Introduction}
Wireless local area networks (WLANs) operating on IEEE 802.11 standards form the backbone of contemporary IoT deployments. However, their open-medium nature leaves them inherently vulnerable to malicious probes, address spoofing, Denial-of-Service (DoS) floods, and unauthorized port reconnaissance. While enterprise networks rely on centralized Intrusion Detection Systems (IDS) and dedicated honeypots hosted on high-performance servers, edge nodes and small-scale field operations lack lightweight, battery-operable physical security sentries capable of real-time threat monitoring and network extension.

The introduction of modern microcontrollers featuring a 32-bit RISC-V processor with integrated $2.4\,\text{GHz}$ Wi-Fi 6 (802.11ax) and Bluetooth 5 (LE) connectivity, such as the ESP32-C6, presents new opportunities for edge security applications. Exploiting raw packet capture capabilities alongside high-level TCP/IP stack manipulations enables compact hardware devices to act simultaneously as network monitors, decoy targets, and Internet access repeaters.

This study presents the architecture and implementation of the \textbf{Rogue Wi-Fi Access Point Detector} (configured with the local broadcast SSID \texttt{Scarlet ESP32-C6}), a multi-functional wireless security sentry and bridge. Operable via a debounced multi-click physical interface and standard I2C display peripherals, the system delivers six core execution modes: targeted ICMP/Data packet sniffing, high-throughput traffic monitoring, station connection logging, frame flood alarm triggers, active TCP honeypots across industrial ports, and an automated LWIP-driven NAPT Wi-Fi range extender.

\section{Related Work}
Wireless security monitoring at the embedded edge has evolved through specialized firmware implementations. Early research utilized ESP8266 and ESP32 microcontrollers primarily for frame injection or passive packet capturing. Dedicated portable security tools typically focus on single operational domains: either acting purely as passive network sniffers, standalone rogue access points, or simple software repeaters.

In the domain of embedded deception, hardware honeypots have traditionally been constrained by full Linux-based single-board computers (such as the Raspberry Pi) running heavy software suites. Microcontroller-based honeypots remain scarce due to limited memory buffers and simplified TCP/IP stack implementations. Conversely, Wi-Fi repeater solutions on microcontrollers often operate at Layer 2 or require explicit static routing rules, rarely integrating automated open-network discovery with Layer-3 NAPT translation and real-time security sentry modes within a unified non-blocking execution state machine.

The Rogue Wi-Fi Access Point Detector addresses these limitations by consolidating promiscuous frame analysis, active TCP honeypots, station logging, and LWIP NAPT routing into a single low-power RISC-V microchip architecture.

\section{Problem Statement}
Contemporary portable wireless security tools suffer from key operational trade-offs:
\begin{enumerate}
    \item \textbf{Single-Function Constraints:} Most embedded security devices perform frame sniffing or AP spoofing independently without providing network bridging or deception capabilities in the same device.
    \item \textbf{Heavy Resource Overhead:} Software-defined wireless monitoring solutions generally depend on resource-heavy operating systems, preventing compact deployment and immediate low-power cold-boot readiness.
    \item \textbf{Lack of Local Physical Alerting:} Threat notifications are frequently routed exclusively to remote web dashboards, leaving field engineers without immediate acoustic or visual feedback when local RF traffic anomalies or direct port scans occur.
    \item \textbf{Bridging Limitations:} Standard Wi-Fi repeaters lack automated security auditing of incoming softAP clients and automated, signal-strength-driven connection to open access networks.
\end{enumerate}

The system utilizes dedicated GPIO pin mapping optimized for the ESP32-C6 pinout:
\begin{itemize}
    \item \textbf{Buzzer Output:} GPIO 0 (PWM frequency generation)
    \item \textbf{Button Input:} GPIO 1
    \item \textbf{Blue Activity LED:} GPIO 2
    \item \textbf{Orange Warning LED:} GPIO 3
    \item \textbf{Addressable RGB LED:} GPIO 8 (NeoPixel single-wire signal)

Each of the four active components, the buzzer, the push button, and the two indicator LEDs, is current-limited through a dedicated $1\,\text{k}\Omega$ resistor.

\subsection{Software Architecture \& Feature Execution}
The firmware relies on an asynchronous event loop driving six distinct execution states:

\subsubsection{Feature 1: AP Ping Monitor}
Sets the Wi-Fi stack into promiscuous mode via \texttt{esp\_wifi\_set\_promiscuous()}. The callback \texttt{sniffer\_callback()} parses incoming IEEE 802.11 data frames, matching destination MAC addresses against the module's softAP MAC. If packet throughput exceeds $10\,\text{pkts/sec}$, a visual warning state (Yellow RGB) and single acoustic tone ($2400\,\text{Hz}$) are fired.

\subsubsection{Feature 2: AP Data Monitor}
Monitors total cumulative packet counts ($\text{Total Rx}$) and real-time interval throughput every $200\,\text{ms}$. RGB brightness scales dynamically with packet activity to visually indicate payload transfers.

\subsubsection{Feature 3: Client Access Logger}
Binds to \texttt{ARDUINO\_EVENT\_WIFI\_AP\_STACONNECTED} events. Upon station association, the client's hardware MAC address is parsed, formatted into standard hexadecimal notation, logged to display buffers, and accompanied by a $2400\,\text{Hz}$ tone notification.

\subsubsection{Feature 4: Flood Attack Monitor}
Evaluates data frame arrival rates over 1-second interval windows. If frame intensity exceeds $\text{FLOOD\_THRESHOLD} = 100\,\text{pkts/sec}$, the system enters a high-priority warning state: activating an alarm siren ($2500\,\text{Hz}$), setting the RGB LED to critical red, and warning on the OLED interface.

\subsubsection{Feature 5: Port Scan Honeypot Sentry}
Instantiates four simultaneous \texttt{WiFiServer} listeners on key network service ports: FTP (21), SSH (22), HTTP (80), and HTTPS (443). When an external scanner connects to any listener, the connection is immediately accepted, flushed, and closed to prevent resource exhaustion. The hit triggers a non-blocking 3-second alternating siren ($1800\,\text{Hz} - 2800\,\text{Hz}$) accompanied by red-purple RGB strobing.

\subsubsection{Feature 6: NAPT Wi-Fi Repeater}
Operates in dual AP+STA mode (\texttt{WIFI\_AP\_STA}). Users can select between connecting to a pre-configured target SSID (using WPA2 credentials) or initiating an asynchronous non-blocking scan for open networks. In open scan mode, the module evaluates surrounding open APs and automatically connects to the access point with the highest Received Signal Strength Indicator (RSSI).

Upon successful STA connection, the system enables Layer-3 NAPT within the LightWeight IP stack:
\begin{equation}
\mathtt{ip\_napt\_enable}\left(\mathtt{softAP\_IP}, 1\right)
\end{equation}
Thread safety is maintained by wrapping NAPT instantiation within \texttt{LOCK\_TCPIP\_CORE()} and \texttt{UNLOCK\_TCPIP\_CORE()} blocks. The SoftAP DHCP server is reconfigured to dynamically forward active Upstream STA DNS addresses (or Google DNS $8.8.8.8$ as fallback) to connected clients.

Promiscuous frame filtering successfully parsed IEEE 802.11 data packet headers without triggering buffer overflows or execution stalls. Traffic flood conditions for Feature 4 were generated using the continuous ping utility within the PingTools Android application (Google Play Store), directed at the device's SoftAP interface, reliably exceeding the $100\,\text{pkts/sec}$ threshold and triggering the critical alarm state. During Feature 5 honeypot testing, port scans executed from the PingTools application against ports 21, 22, 80, and 443 were detected instantly, triggering the alternating acoustic/visual siren in under $3\,\text{ms}$ while preserving non-blocking state loop execution.

In Feature 6 execution, open-network acquisition required $4.613\,\text{s}$ to identify and lock onto the strongest available open access point (RSSI $-30\,\text{dBm}$), while the subsequent NAPT and DHCP/DNS reconfiguration completed in under $1\,\text{ms}$, confirming the operation's synchronous, in-memory nature. Thread locking via \texttt{LOCK\_TCPIP\_CORE()} ensured that dynamic DNS reallocations did not cause LWIP stack panics.

\section{Challenges Faced}
Developing and debugging the unified architecture on the ESP32-C6 hardware platform revealed several critical firmware and hardware integration challenges:

\begin{enumerate}
    \item \textbf{Hardware Serial Debugging vs. Native USB CDC:} During initial development, serial output failed to stream or hung indefinitely upon startup. This was traced to the ESP32-C6 native USB-CDC driver configuration conflicting with the hardware UART peripheral. Disabling USB CDC on Boot in the IDE build flags routed standard \texttt{Serial.print()} logs directly over default hardware UART, restoring full serial telemetry.
    \item \textbf{Wi-Fi Stack Mode Transitions:} Transitioning the Wi-Fi radio between pure promiscuous access-point mode (\texttt{WIFI\_AP}) and dual repeater mode (\texttt{WIFI\_AP\_STA}) caused memory corruption within internal ESP-IDF driver structures. This required implementing an explicit teardown sequence calling \texttt{WiFi.mode(WIFI\_OFF)} and detaching sniffer callbacks prior to re-initializing new Wi-Fi modes.
    \item \textbf{LWIP Thread Safety \& Core Locking:} Dynamic invocation of \texttt{ip\_napt\_enable()} while active client packets passed through the interface caused intermittent memory panics. Wrapping network interface initialization inside \texttt{LOCK\_TCPIP\_CORE()} and \texttt{UNLOCK\_TCPIP\_CORE()} macros resolved kernel race conditions.
    \item \textbf{Non-Blocking Multi-Peripheral UI Execution:} Synchronizing piezo buzzer PWM sweeps, NeoPixel WS2812 color transitions, SSD1306 display updating, button debouncing, and multi-port honeypot polling without introducing blocking \texttt{delay()} calls required a strict timestamp-driven state engine utilizing \texttt{millis()} interval counters across all loops.
\end{enumerate}

\section{Conclusion}
The Rogue Wi-Fi Access Point Detector demonstrates the viability of executing multi-layered wireless security monitoring, active deception, and network bridging on a single low-power RISC-V microcontroller. By consolidating promiscuous frame sniffing, flood alarms, multi-port honeypots, and LWIP-driven NAPT repeating into an accessible hardware device, the system offers field engineers an adaptable tool for wireless auditing and network extension. Future iterations will focus on integrating Bluetooth Low Energy (BLE) attack detection, battery management telemetry, and cloud reporting via MQTT protocols.
